Mockup for ruling · Issue #8 · M0

Presentator Lobby

Login, the deck list, the deck page, Settings (admin), and Account. An admin creates every account and sets instance language, theme, sources, and users under Settings. Decks arrive exclusively via Git — from a repository on any host, which the server only mirrors. Once blessed, this mockup is frozen; after that the expectation lines are ruled and cut.

failedtriangle, red — only you can fix this

reachablefilled circle, green — last read
Errortriangle, red — access or host
never fetcheddashed square, grey

Account state: shape and color

activefilled circle, green — can log in
deactivatedsplit circle, grey — switched off, not broken
Adminrole is a label, never a color

Deliberately left out

  • OAuth, GitHub App, host picker — one read-only secret per source, the same form for every host (line 1)
  • Writing back to Git — the server is a mirror, never the origin (line 1)
  • Showing the secret again — after entry it can only be renewed (line 12)
  • New deck / upload — decks are created in Git (line 4)
  • Name filter — twenty decks don't need one (line 18)
  • Sign up, forgot password — an admin creates the account and resets the password (lines 14, 14b)
  • Start in M0 — the two views are the way into the talk; the co-presenter run arrives with M1 (line 10)
  • Build progress bar — the server doesn't know percentages
